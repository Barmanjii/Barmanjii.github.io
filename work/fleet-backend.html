One backend, every screen

The API behind the web dashboard and the mobile app, serving many customers at once, each seeing only what they should.

A simplified, general version of how this works. No company code, customer names or internal details.

The problem

Customer admins, operators and internal teams all need the same fleet data: robots, reports, alerts, users and licenses. They use it on the web and on their phones, and each person should see only what their role allows.

How it works

One multi customer REST API in FastAPI serves both the React dashboard and the Flutter app. Access rules live in one place as policies (OPA), with the result cached in Redis so checks stay fast. Heavy work like reports and usage alerts runs in the background, and the app gets push notifications.

What I built

  • Most of the backend since 2022: reports, bulk usage reports, usage alerts, license APIs, region routing and transfers.
  • In the mobile app (2026): usage reminders, a watchlist, alerts, the activity tab, mission scheduling, ticket summary, the fleet screen and translations.
  • Dashboard screens for region aware login, transfers and licenses.

Choices that mattered

  • One API for both screens. A fix or a new feature lands once.
  • Access decided in one place. Policies, not checks scattered across endpoints.
  • Heavy work in the background. Reports and alerts never slow down a page. And on the screen: if an operator has to think twice, it is not done.
