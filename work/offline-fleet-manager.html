A fleet manager with no internet

The factory said no internet. So the fleet manager moved onto the factory floor.

A simplified, general version of how this works. No company code, customer names or internal details.

The problem

A factory would not let its robots or any software reach the internet. It still needed what a fleet manager gives: missions, maps, robot status and an operator screen.

How it works

The whole fleet manager runs on site as a set of containers. Robots connect to a local message broker, and every robot proves who it is with its own certificate (mutual TLS). Robots and the fleet manager talk in VDA 5050, the open standard for mobile robot fleets, so the message format is public and documented.

What I built

  • The offline install: the fleet manager, broker and operator UI packaged as one Docker stack.
  • Per robot certificates and mutual TLS on the broker.
  • A large share of the fleet manager's code in 2026, on top of the VDA 5050 standard.

Choices that mattered

  • Everything on site. No cloud dependency means nothing breaks when the factory's rules do not allow a connection.
  • Mutual TLS even on a closed network. A device on the factory network cannot pretend to be a robot.
  • An open standard. VDA 5050 messages are documented, which makes testing and new robots easier.
