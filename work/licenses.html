Licenses that survive a power cut

A broken license file can stop a working robot. Now it is hard to break and quick to fix.

A simplified, general version of how this works. No company code, customer names or internal details.

The problem

Every robot needs a valid software license to run. If the license file is lost or damaged in the field, a robot that works fine stops, and getting it back used to be a manual job.

How it works

The backend issues a signed license. The robot checks the signature itself, so it does not need the internet to know its license is genuine, and checks in with the backend when it can. The license file is written safely, so a power cut cannot corrupt it. When a license does need replacing, an admin reissues it from the dashboard, which needs a permission and is recorded.

What I built

  • The license manager on the robot.
  • The license APIs on the backend, then a reissue flow that needs a permission and leaves an audit trail.
  • Reissue and download in the dashboard, and a license reset in the field app.
  • After a field incident: hardened how licenses are stored, with tests that reproduce the failure.

Choices that mattered

  • Check offline. Robots are often offline. A license check should not depend on a network.
  • Write safely. The same copy then swap pattern as every other file the robot depends on.
  • Reissue is gated and recorded. Fixing a robot is quick, and every fix leaves a trail.
